WEEK 02 · 기획·구현

아이디어를 작동하는 서비스로 전환

01

사용자·상황·불편 중심의 문제 정의

  • 문제 발굴: 반복 수작업, 업무 비효율, 장시간 작업, 실수 비용이 큰 업무 파악
  • 문제 구체화: 사용자가 언제 어떤 불편을 겪는지 정리
  • AI 활용: 아이디어·문서·코드·디자인 초안 작성
  • 사람의 판단: 해결할 문제와 작업 범위 선택, 실제 결과 검토·결정
02

핵심 솔루션 선정 및 MVP 범위 설정

작게 만들기 → 실제로 사용하기 → 결과로 검증하기 → 필요한 기능만 확장하기
  • 핵심 가치 정의: 사용자가 서비스를 이용한 후 얻어야 할 구체적인 결과를 먼저 설정
  • MVP 구성: 없어지면 서비스 가치가 사라지는 핵심 기능 한 가지를 중심으로 실제 사용 가능한 첫 버전 제작
  • 범위 통제: 기능을 ‘이번에 만들 것·이번에는 제외할 것·향후 추가할 것’으로 구분하여 불필요한 확장 방지
  • 단계적 고도화: 1차 MVP가 작동한 후 핵심 User Flow에 필요한 Auth·DB·AI API만 하나씩 추가하고 화면과 데이터로 결과 확인
03

3~5단계 User Flow 및 완료기준 설계

진입 → 입력 → 실행 → 결과 확인

범위 통제불필요한 기능 추가 방지
구현 순서Codex에 작업 순서 전달

오류 점검빈 입력·처리 실패 상황 사전 확인
04

HTML 기반으로 Codex 작업 및 제작

  • 작업 기준: 목적·사용 흐름·화면 구성·완료 조건 정리
  • 계획 확인: 필요한 파일과 구현 순서 검토
  • 제작: HTML 기반 화면과 핵심 기능 구현
  • 개선: 실제 화면 확인 후 오류·문구·디자인 수정
